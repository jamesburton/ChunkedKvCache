# Chunk-cache upstream PR split Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the chunk-KV-reuse work on the fork branches into an ordered series of small, individually building and
testing PR branches off `dev`, and decide what never goes upstream.

**Architecture:** One preparatory refactor on a new fork branch (`feature/chunk-cache-upstream-prep`) splits
`DotLLM.ChunkReuse` into a light core plus two heavy assemblies and moves the few tests that cross PR boundaries; after
that every PR branch is `origin/dev` + `git checkout <prep or milestone commit> -- <paths>` + its `slnx` / csproj hunks.
Server PRs are cut at the server branch's own milestone commits. The research lab stays on the fork.

**Tech Stack:** git worktrees, .NET 10 SDK (`10.0.401` verified), xUnit, `DOTLLM_SKIP_VULKAN=1`.

**Spec:** `docs/superpowers/specs/2026-11-02-chunk-cache-integration.md` (rev 3); Phase I plan
`docs/superpowers/plans/2026-11-02-phase-i-integration.md` (Tasks 21, 22; this plan replaces Task 22's Vulkan-only split
and Task 21 Step 1's PR list); umbrella `docs/release/chunk-cache-issues/00-umbrella.md`.

## Global Constraints

- dotLLM `CLAUDE.md`: PRs target `dev` (never `main`); **issue first, one issue per PR**; small diffs; rebase on `dev`
  often; docs updated in the same PR; STJ source-gen DTO rule (nullable property + resolved default, a
  `JsonContextDefaultsTests`-style guard per new context); correctness tests shown to fail against a mutant, recorded in
  the PR body; `Closes #N` does not auto-close on `dev`.
- **Nothing is filed, pushed or opened without the user's explicit per-PR approval.** dotllm-97 / the user file issues
  and merge. Branches below are local until then.
- Never switch branches in the shared `C:\Development\dotLLM` checkout; one worktree per PR branch under
  `C:\Development\dotLLM\.claude\worktrees\`.
- Builds `-m:2`; CPU tests with `DOTLLM_SKIP_VULKAN=1`; GPU-gated tests only under the GPU lock with the user's go-ahead.
- `feature/chunk-cache` is updated from `dev` by **merge**, never rebase (Phase I plan). PR branches are cut fresh and
  rebased.
- `#1547` (client package, open) is not re-split.
- The research lab (`benchmarks/ChunkKvLab`) and research-only library code never go upstream (§1).

## Review Focus

- **A cut that builds only because a later PR's file leaked in.** Each PR branch is built from a clean worktree of
  `origin/dev` + its predecessors; never from a tree that had the full source branch checked out. Task 3 Step 4.
- **Unresolved `<see cref>` to a type in a later PR** (CS1574 is an error: warnings as errors + XML docs). Verified: 8-10
  such crefs per library cut. Fixed once in the prep branch (Task 1 Step 3).
- **Byte-exact contract fixtures.** `tests/DotLLM.Tests.Unit/ChunkCache/Fixtures/**` must land with the `.gitattributes`
  `-text` line in the same PR (PR 5) or `fixtures.sha256` fails on a CRLF checkout. Task 7 Step 2.
- **Shared one-line files** (`dotLLM.slnx`, `Directory.Packages.props`, unit-test csproj) collide with `#1547` and with
  each other's PRs: each PR adds only its own lines; rebase after every merge. Task 3 Step 2.
- **Release assets change** when a packable project lands (`release.yml` packs the whole solution and attaches every
  `.nupkg`). Each PR that adds a project states it in its body (§4).
