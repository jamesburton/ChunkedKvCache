## Verdict

1. Structure-aware recompute selection from a static reference graph: OPEN (adjacent work exists, target not done). The only verified static-analysis-in-KV work is CodeComp (2604.10235), which uses Joern Code Property Graph priors, but for KV eviction/compression in a single context, not for choosing which tokens to recompute when independently encoded chunks are stitched. Mesh-LLM issue #1653 lists "structure-aware anchors, def-use preservation" for non-prefix code reuse as an unimplemented proposal (no PR), which signals the idea is in the air but unbuilt. Every verified chunk-reuse paper (KVBoost, KV Packet, SemPIC, MiniPIC, Irminsul, KV-Repurpose, 2603.20218) selects tokens by deviation/boundary/learned adapters and evaluates on RAG/QA, not code reference graphs. Caveats: abstracts only, method sections not read; search is a US web index, so a niche paper could be missed. CodeComp is a reusable graph-extraction precedent and a competing-claim risk.
2. Content-aware chunking with incremental re-encode: PARTLY COVERED; the code-specific and incremental parts are open. Generic content-aware boundaries exist: KVBoost (punctuation-nudged), Irminsul (content-defined chunking hashes), learned segmentation for block attention (2605.15913), all verified. None uses function/class/AST boundaries or reports re-encode cost after a file edit. Incremental edit is addressed only as prefix-cache hygiene (ECA issue #519, append-don't-rewrite advice) and for structured-field edits (2606.17107, unverified). Function-level chunking with build-cache-style invalidation of dependents on edit: no source found.
3. Competitors to track: CodeComp (graph-guided, compression), KVBoost (4.49x TTFT on bug localisation, Qwen2.5-3B; single author, odd arXiv date, treat cautiously), KV Packet / SemPIC (recompute-free trained alternatives), LMCache CacheBlend (tooling baseline). No 2026 follow-up of CacheBlend/EPIC/APE/TurboRAG/KVLink/Cartridges/REFRAG targeting code was found.
